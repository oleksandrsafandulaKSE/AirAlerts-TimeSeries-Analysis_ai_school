# M1 plan v1 — Clean data → hourly grid with target and mask

Status: APPROVED v1.1 (human decisions 2026-10-12 22:20 applied). Supersedes `plans/archive/M1-v0.md`.
Implements ROADMAP M1 under CLAUDE.md and D-002, D-008, D-010, D-011, D-013, D-017, D-020, D-021.

## 1. Goal
From the official file only, produce per unit (24 units) and per UTC hour t:
`active_at_t`, `gap_mask`, `mask`, `y` (onset in (t, t+H]), plus the shared alert table and the
per-unit onset/interval lists that M2 will reuse. No features, no baselines, no model.

## 2. Definitions (fixed here so two people code the same thing)
All timestamps tz-aware UTC. All intervals half-open `[a, b)` (D-021). H = 1h (config).

- **Alert** = one deduplicated row of the shared format (`source, alert_id, unit, level,
  started_at, finished_at, alert_level`). `finished_at` may be NaT (end unknown).
- **Counting interval of an alert (D-020)**: `[started_at, eff_end)` with
  `eff_end = min(finished_at, started_at + 24h)`; if `finished_at` is NaT, `eff_end = started_at + 24h`.
  This is causal: at any t, whether t is inside it depends only on `started_at ≤ t` and on
  whether `finished_at ≤ t` (already observed) — never on an end later than t.
  Observed ends (`finished_at ≤ t`) may be used for state at t; no end later than t may ever be used
  (M2 features included). `finished_at` enters the rules ONLY through `eff_end`; the ">24h" counts in §6
  are printed only. Missing `finished_at` = end unknown → 24h cap (count printed).
- **Zero-duration alerts** (`finished_at == started_at`): if step 0 finds none, no rule. If some exist:
  the start is still a unit onset, the alert masks nothing, count printed.
- **Level filter (D-017 #4)**: `target_levels="any"` uses all alerts; `"red"` keeps only
  `alert_level=="red"` BEFORE building intervals (so a red start during a yellow is an onset and
  yellow never masks). `"red"` on a frame where all `alert_level` are empty (official) → `ValueError`.
- **Unit intervals** = union of counting intervals of all levels (oblast/raion/hromada) of the unit,
  merged when overlapping OR touching (`[a,b)` and `[b,c)` → `[a,c)`). A 1-minute gap → two intervals.
- **Unit onset** = start of a merged unit interval. (Two alerts starting at the same instant → one onset.)
- **active_at_t** = t lies in some merged interval (`start ≤ t < end`).
  So an alert starting exactly at t makes t active; an alert ending exactly at t does not.
- **y(t)** = 1 if any unit onset lies in `(t, t+H]`, else 0. On rows with `active_at_t == 0`
  this equals "any raw alert start in (t, t+H]" (tested as an independent check).
- **gap_mask(t)** (D-013), with the approved gap `G = [g0, g1)` from config: 1 if
  (a) the label window `(t, t+H]` touches G: `t < g1 and t + H ≥ g0`, or
  (b) t is in the post-gap uncertainty window `[g1, g1 + 24h)`: an unrecorded alert that started
      inside G could still be within its first 24h, so `active_at_t` is unknowable there.
  On gap_mask rows `y = NaN` (missing, not "no alert").
- **mask** = `active_at_t OR gap_mask`. Rows used for the onset task later = `mask == 0`.
- **Grid**: `t` ∈ `[grid_start, grid_end)` step 1h, `grid_start = 2022-03-15 00:00`,
  `grid_end = 2026-09-07 00:00` (= test end, D-021). Raise if `grid_end − 1h + H > coverage_end`,
  where `coverage_end = 2026-09-07 05:28` UTC is an explicit config value (D-007), NOT the max
  timestamp in the file (a late `finished_at` must not extend coverage).
  Alerts before `grid_start` are still used (they can make early rows active).

## 4. Steps
0. **Setup (5 min).** `.venv` with `/usr/local/bin/python3.13`; install; `pip freeze` → pin.
   Download the official CSV once; print its header and `value_counts` of the oblast column and
   level column; check NaT counts in `finished_at` and `finished_at < started_at`. If the
   columns, names, or counts differ from §2/§6 assumptions → STOP and report (no workaround).
1. **regions.py (10 min).** Official names copied verbatim from step 0's printed list (exact match,
   no fuzzy). API UIDs (alerts.in.ua; consistent with the dump manifest: 200 for 3–5, 8–31,
   404 for 6, 7): Khmelnytska 3, Vinnytska 4, Rivnenska 5, Volynska 8, Dnipropetrovska 9,
   Zhytomyrska 10, Zakarpatska 11, Zaporizka 12, Ivano-Frankivska 13, Kyivska 14,
   Kirovohradska 15, Mykolaivska 17, Odeska 18, Poltavska 19, Sumska 20, Ternopilska 21,
   Kharkivska 22, Khersonska 23, Cherkaska 24, Chernihivska 25, Chernivetska 26, Lvivska 27,
   Donetska 28, Kyiv City 31 (excluded: Luhanska 16, Crimea 29, Sevastopol 30).
   Groups per D-011. Border table hard-coded (used in M2; human eyeballs it once).
2. **config.py (5 min).** `official`: train `[2022-03-15, 2026-06-29)`, val `[2026-06-29, 2026-07-27)`,
   test `[2026-07-27, 2026-09-07)`, grid as §2, `H=1h`, `target_levels="any"`,
   `approved_gaps=[[2026-08-29 00:00, 2026-09-03 00:00)]` (APPROVED) + 24h post-gap mask,
   `coverage_end=2026-09-07 05:28`,
   `expected_raw_rows=299_275`, `expected_duplicate_rows=113_845`, `standing_cap=24h`.
3. **data.py (15 min).** Read every column as raw strings. Order of operations, each with a printed count:
   (1) raw rows → raise if ≠ 299,275 (the file is frozen; a change means re-check, not continue);
   (2) drop exact duplicate rows ON THE RAW STRINGS (before any parsing) → raise if dropped ≠ 113,845
   (if it differs: STOP and report); then re-check 0 duplicates remain; only now parse times as UTC
   (`utc=True`; strings without offset are UTC per CLAUDE.md);
   (3) drop excluded units (Luhanska) → print rows dropped;
   (4) map names via `regions.py` → unknown name raises;
   (5) raise if the unit set ≠ exactly the 24 canonical keys;
   (6) raise on null `started_at` or `finished_at < started_at` (if step 0 finds any, STOP, ask);
   (7) `alert_id` = sha1 of the raw row strings joined by `\x1f` (stable across runs); `alert_level = ""`;
   `source="official"`. Return columns in the exact shared order.
4. **grid.py (20 min).** Per unit: effective intervals → filter by `target_levels` → sort → merge
   (touching merges) → onsets = merged starts. `active_at_t` via `searchsorted` on merged
   starts/ends; `y` via onset counts `searchsorted(onsets, t+H, 'right') − searchsorted(onsets, t, 'right') > 0`.
   **Gap detection:** national (all 24 units) count of raw alert starts per UTC hour over the
   whole data range; a gap = a run of ≥ 24 consecutive hours with zero starts; reported as
   `[first empty hour, first non-empty hour)`. `check_gaps()` raises unless every detected gap
   lies inside an approved gap AND every approved gap contains a detected gap. Approved gaps
   then drive `gap_mask` (§2). Detected and approved edges are both printed.
   **Base-rate check (no test labels in M1):** only rows with `t < 2026-07-27` (test start). Mean `y`
   on `mask==0` rows per UTC quarter, pooled over units (2026Q3 = 1 Jul–26 Jul only); same per group
   for printing. Raise if any quarter from 2025Q1 onward is < 50% of the 2024 average.
5. **run_all.py (5 min).** First raises if `sys.version_info[:2] != (3, 13)`. Calls the above; prints §6; writes `reports/<run>/`:
   `run_meta.json` (config name + all dates, H, target_levels, data URL + sha256, raw/dedup/final
   row counts, data range, git commit (+dirty flag), python + package versions, `features: []`),
   `m1_checks.json` (all §6 counts, gaps), `base_rate_by_quarter.csv`, `base_rate_by_group.csv`.
   M1 exception to D-017 #5: no `metrics.json/metrics.csv`/plots yet (no metrics exist in M1).
   The grid is NOT saved (recomputed in seconds; avoids pyarrow). Any `DataQualityError` → exit ≠ 0,
   nothing written.
6. **Tests + reviewer (15 min)** per milestone-protocol.

## 5. Tests (expected values written by hand, not computed by the code under test)
Toy unit "A", H=1h, day D, times `HH:MM` on D unless stated.

**test_grid.py**
1. Alert `[00:30, 01:10)`: rows 00:00 → active 0, y 1; 01:00 → active 1 (masked); 02:00 → active 0, y 0.
2. Start exactly at t+H: alert starts 02:00 → y(01:00)=1; row 02:00 active 1; y(02:00)=0.
3. Start exactly at t: same alert → row 02:00 masked (start ≤ t).
4. End exactly at t: `[01:00, 03:00)` → 02:00 active 1, 03:00 active 0.
5. Touching `[01:00,02:00)`+`[02:00,03:00)` → onsets `[01:00]`, 02:00 active 1.
   1-minute gap `[01:00,02:00)`+`[02:01,03:00)` → onsets `[01:00, 02:01]`, row 02:00 active 0, y 1.
6. Cross-level union: hromada alert `[10:15,11:00)` and no oblast-level row → y(10:00)=1.
   Raion alert `[10:30,10:50)` inside an oblast alert `[10:00,12:00)` → onsets `[10:00]` only.
7. Standing (D-020): alert starts D 00:00, `finished_at` = D+3. Row D 23:00 active 1; row D+1 00:00
   active 0 (exactly start+24h is outside). A second hromada alert at D+1 05:30 → y(D+1 05:00)=1,
   row D+1 06:00 active 1. Same frame with `finished_at = NaT` → identical grid.
   Alert of exactly 24h `[00:00, D+1 00:00)` → identical to the capped one.
8. Mask truncation invariance: random seeded toy data (3 units, ~200 alerts, mixed levels, ~10%
   longer than 24h, some NaT ends). For 20 random t: build `active_at_t`/`mask` from full data and
   from data truncated at t (drop `started_at > t`, set `finished_at = NaT` where `> t`); rows at t equal.
   Plus fixed truncation cases for one alert `[00:00, 05:00)`: t = 04:59→row 04:00, t = 05:00 (end),
   and for a 3-day alert t = start+23h and t = start+24h (cap).
   **Negative control:** the old D-009 mask (drop alerts whose FINAL duration > 24h, else full
   `[start, finished_at)`) run through the same truncation checker → the checker must report a
   mismatch (test asserts it is caught).
9. Brute-force cross-check on the same random data: an independent loop over raw alerts,
   `active = any(start ≤ t < min(end, start+24h))`, `y = any(t < start ≤ t+H)` on active==0 rows;
   must equal the vectorised grid on every row, including an exact `mask` comparison per unit.
   Plus per-unit invariant: no row with mask 0 and active 1.
10. Level filter: API-format frame, yellow `[01:00,04:00)`, red starts 02:30. `"any"` → onsets
    `[01:00]`, rows 02:00/03:00 masked. `"red"` → y(02:00)=1, row 02:00 active 0, row 03:00 active 1.
    Official frame + `"red"` → `ValueError`.
11. Gap (toy approved gap `[D+1 10:00, D+1 14:00)`, H=1): row 09:00 gap_mask 1 (t+H = 10:00 ≥ g0);
    08:00 gap_mask 0; 13:00 gap_mask 1; rows 14:00 … D+2 13:00 gap_mask 1 (post-gap 24h); D+2 14:00 gap_mask 0;
    `y` NaN exactly on gap_mask rows.
12. `detect_gaps`: national starts with a 30h silence → one gap with the hand-written edges; 23h silence → none.
    `check_gaps` raises on an extra unapproved gap, and on an approved gap with nothing detected.
13. Grid shape/DST: grid over 2024-03-30 → 2024-04-02 and 2024-10-26 → 2024-10-29 (UTC): every diff
    exactly 1h, no duplicates, rows = 72 × n_units; tz is UTC. No row with `t + H > grid_end`.
    Alignment: an alert starting 2024-10-27 00:30 UTC (DST night) → y=1 on row 2024-10-27 00:00 UTC
    and active on row 01:00 UTC (parsed from the string, not constructed as a Timestamp).
14. Base-rate check raises on a toy grid with a 2025 quarter at 40% of 2024; passes at 60%;
    rows with t ≥ test start are ignored (a toy test-period quarter at 0% does not raise).

## 9. Risks / assumptions
- Official CSV column names/format are assumed (`oblast`, `level`, `started_at`, `finished_at`);
  verified in step 0, stop if different.
- Other national silences ≥ 24h (e.g. early 2022) would fail `check_gaps` → stop and ask, not auto-approve.
- The base-rate check could fail for a real reason (e.g. D-020 changes frontline masking) → stop and report.
- Expected counts (299,275 / 113,845) were measured by `sort -u` on text; a pandas row-equality
  dedup could differ by formatting (e.g. trailing spaces) → stop and report the difference.
- lightgbm on macOS may need `libomp`; only matters for pinning now, used in M4.
- `.gitignore`: add `!reports/**/*.csv` (approved Q3).
- Limitation (approved): outages hitting only some units are not detectable from the data; not handled.
- Purge rule for M3 (approved): a training row with `t + H = cutoff` is KEPT; written into the M3 plan.
