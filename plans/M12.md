## A. "Any" horizons 6, 12, 24 h
- **Split `M12Split`** (a new frozen dataclass in `newregime/horizons.py`, the only place its dates live; the M6c-1
  `pipeline.Split` requires val end = test start, `pipeline.py:49`, so it is not reused): grid_start, train and
  validation IDENTICAL to `pipeline.first_split()` (train [09-13, 10-04), val [10-04, 10-11)); an UNUSED-FOR-FIT gap
  [10-11, 10-18) (the M6c-1 test week + one day, never a fit or early-stopping row); test week
  **[2026-10-18 00:00, 2026-10-25 00:00) UTC**. Order check: grid_start ≤ train0 < train1 = val0 < val1 ≤ gap_end =
  test_start < test_end. Forecast rows t with t + H ≤ test end (D-022 equality kept); the test stage refuses to run
  before `coverage_end ≥ 2026-10-25 00:00` (+ the run's own coverage checks).
- **Fit-time reconstruction pinned (D-027):** FACT: `nd.load(..., reconstruct_at=T)` reconstructs from ALL stored
  versions (`as_reconstructed_at` keeps the latest version per id, `collect/api_collector.py:580-583`); it does not
  drop versions fetched after T. So `horizons.load_pinned(A_fit)` first FILTERS the inputs — datastore rows with
  `fetched_at` ≤ A_fit, pull-log rows with `fetched_at` ≤ A_fit, holes with start ≤ A_fit — then runs the same
  coverage + reconstruction functions as `nd.load` on the filtered rows. Two separate cut-offs, both recorded:
  **A_fit** (acquisition cut-off) = the `fetched_at` of the last pull in the pull log at the fit run (immutable);
  **R_fit** (event-time reconstruction time) = floor_hour(coverage_end of the FILTERED inputs), so the
  `newregime/data.py:98` guard (reconstruction ≤ coverage_end) always holds. Fit and validation need rows < 10-11
  only; R_fit ≥ 10-11 is asserted. Test: a pull log whose last pull is later than the filtered coverage (e.g. coverage
  ending 2026-10-17 21:06 after filtering) gives R_fit = 21:00, not the unfiltered last hour. Canonical version key = (`id`, `updated_at`, `fetched_at`, `pull_id`); the
  pre-registration stores sha256 of the datastore rows with `fetched_at` ≤ A_fit sorted by that key, of the pull-log
  rows with `fetched_at` ≤ A_fit, and of the holes file rows with start ≤ A_fit. The test stage re-checks these
  prefix hashes (appends allowed; an edit or deletion of a pinned row → refuse; tests for each case) and evaluates on
  a NEW reconstruction at the test-run time (later revisions consumed, D-027), recorded.
- **Fit (no test label read):** for H ∈ {6, 12, 24}: `fit_one(ctx, "any", H, iso_frames)` with test labels blanked as
  in `pipeline.fit`; same features, params, Platt decision rule, baseline tables (D-025 recent rate shrunk to the
  train p_unit). H = 1/3 "any" and yellow/red H = 1/3 are NOT refitted: their artefacts are copied from
  `reports/m6c1/` and their sha256 checked against `reports/m6c1/preregistration.json`.
- **Validation report:** for every (type, H) of the registry (any 1/3/6/12/24, yellow 1/3, red 1/3): Brier, BSS vs
  the rolling recent rate, pooled and within-oblast AUC (≥ 10/10, D-025), PR-AUC and / base rate,
  calibration-in-the-large, reliability plot, on identical eligible support for model / baseline / blend, exclusion
  counts. H = 6/12/24 have no official comparator (none exists); stated.
- **Pre-registration** `reports/m12/preregistration.json`: sha256 of all 9 model/calibrator/table sets, input hashes
  (datastore, pull log, holes) AT FIT TIME, code fingerprint of `newregime/horizons.py` + the M6c-1 fingerprint,
  packages, A_fit and the prefix hashes defined above.
- **Test (scored once, after 10-25):** one exclusive reservation for the week [10-18, 10-25) via `pipeline.reserve`
  (refuses if any overlapping reservation exists, any name), scoped to the NEW horizons as agreed in the definition:
  it scores "any" H = 6/12/24 (model, baseline, blend). Scoring the frozen H = 1/3 fits on the same week is NOT done
  (a scope change for the human; the overlap rule then blocks it on this week). Every check that can fail runs before
  the reservation (as M6c-1). Outputs `reports/m12/metrics.csv`, `reliability.png`, `test_predictions_<type>_h<H>.csv`. Labelled
  EXPLORATORY, one week. Until it runs, the site labels H = 6/12/24 "validation only, not yet tested".
- **Blend on the scored rows (operational rule, out-of-sample only):** `blend.weights` with its `cutoff` argument set
  to the VALIDATION END (10-11), not the train end: window rows s ∈ [max(t − 28 d, 10-11), t − H], 28 d, n₀ = 50,
  distinct onsets. Validation rows (used for early stopping / Platt) never enter the operational weight. For H = 24
  the window has fewer known rows near t; reported (n and rows_used per hour). The published M6c-1 weights (cut-off
  at train end) are used only for the faithful replay (§F).

## B. Live export and the inactive new path
- `scripts/export_m12_models.py` writes `netlify/live/model/m12/`:
  - per (type, H): LightGBM dump (trees up to best_iteration), calibrator, baseline tables (alpha, p_unit),
    feature list and category order, `trained_through` (= train end), `available_at` (export time), sha256;
  - `blend_seed.json` (per model version, per (type, H)): eligible rows s ∈ [10-11 00:00, T_seed], keyed (unit, s);
    fields p_model, p_baseline, and EITHER y + onset event ids "unit|onset" (labelled rows: s + H ≤ T_seed) OR
    `label: pending` (rows with s + H > T_seed, see the seam rule below). **T_seed = the test start
    (2026-10-18 00:00) for the export made before the test stage**, so no label of the reserved week is read; it is
    rebuilt (new T_seed) only after the test is scored. Reconstruction (D-027), labelled;
  - **seam:** the seed holds every eligible row with s ≤ T_seed (predictions need inputs ≤ s only); rows with
    s + H > T_seed carry `label: pending` and are labelled later by the live label function (air-raid onsets in
    (s, s + H] from the alerts known at labelling time, after s + H + SETTLE, coverage over [s − 24 h, s + H]) —
    so no row in (T_seed − H, T_seed] is lost (test);
  - live extension: archived live snapshot rows (§D) with issue time τ_s > T_seed; identity = (unit, snapshot hour),
    but the row's time for labels, maturity and the blend window is its ACTUAL issue time τ_s (label window
    (τ_s, τ_s + H]), never the hour start; seed and live never overlap (a live row with τ_s ≤ T_seed is ignored,
    counted); a row enters w(τ) only if τ_s + H ≤ τ, its label is settled and it passes the §D eligibility; rows with
    τ_s < τ − 28 d are evicted; onset events counted once by id; a NEW model version starts its own seed;
  - **while the flag is absent the new path stores p_model and p_baseline only**: no w, no blended p, no label is
    resolved for a row whose label window touches the reserved week [10-18, 10-25) — pending rows are resolved only
    after the §A test stage;
  - `parity_sample.json`: Python predictions (model, calibrated, baseline, blend) at ≥ 200 (unit, τ) per (type, H) with
    τ + H ≤ test start (no reserved-week label), including τ inside an under-alert period, right after an alert ends,
    a DST day, a coverage hole edge.
- `models.mjs`: for each τ, every (type, H): features from the air-raid-only alerts known at τ (D-045; `live.mjs`
  filters `alert_type == "air_raid"` for this path; the M8 path is untouched), mask per type (that level active at τ,
  D-020 cap), model → calibrator → recent-rate baseline → blend weight → p. Errors in one (type, H) never block the
  others; shown as an explicit state, never a silent fallback.
- **Activation flag** `netlify/live/model/m12/ACTIVE` absent → the new path computes and archives snapshots (§D) but
  the map and `/api/forecast` keep the M8 output, and **no metric of an m12 series is computed, stored or shown while
  the flag is absent** (the scorer skips inactive versions; test) — so nobody sees reserved-week performance before
  the §A test. The switch (§E) is allowed only after the §A test stage has written `reports/m12/metrics.csv`; the
  scorer then scores m12 series only from τ ≥ the activation time.

## C. Red-share rule check (exploratory, API data)
- Conditional event (definition): an "any" onset (merged air-raid interval start, D-020 cap); colour = red if any red
  air-raid alert starts at that instant, else yellow; escalations inside a running interval are not onsets.
- N = 0 → no prediction (counted); coverage of u incomplete in (τ − 7 d, τ] → excluded (counted). Comparator: the
  national share of red-coloured onsets with start in (τ − 7 d, τ] over units with full coverage in that window.
  Every window (rule, coverage, national comparator) is anchored at the same τ defined below.
- **What is evaluated = the displayed hourly forecast.** For each onset o of unit u, the forecast that the page showed
  just before it: τ = floor_hour(o) if o > floor_hour(o), else o − 1 h (so o ∈ (τ, τ + 1 h]); rule value =
  R / N over u's any-onsets with start in (τ − 7 d, τ]. Outcome = the colour of o.
- Rows: onsets with τ ≥ history_start + 7 d and o < 2026-10-18 00:00 (the reserved week stays unread).
- Report `reports/m12/redshare.csv`: rows, base rate (share red), Brier rule vs national, BSS, pooled and
  within-oblast AUC (≥ 10/10), calibration-in-the-large, per group.

## D. Versioned snapshots and the (model, target, H) scorer
- Snapshot store `snapv2/<UTC hour>` (the M11 `snap/` keys stay for the M8 series): first successful write in the
  hour wins (M11 A1 rules: `late` ≥ 15 min, `written_at`), holding for every (type, H): model version, p_model,
  p_baseline, w, p, state, caution.
- `check.mjs` generalised: one series per (model version, type, H); a row (u, τ) is scored only when
  now ≥ τ + H + SETTLE and coverage covers [τ − 24 h, τ + H] continuously; label = a type-T onset in (τ, τ + H]
  (air-raid only); the M11 eligibility rules (as issued AND reconciled, rejections logged at ≥ τ − 24 h) apply per
  series; BSS pooled per series; never pooled across series. The M8 H = 1 series keeps its current scorer output.
- Retention and daily archive as M11 (35 d of snapshots, frozen daily totals per series).
- No new-model forecast enters the M8 series (test). Inactive versions are skipped by the scorer (test).
- Provenance: live snapshot rows are "as issued"; seed rows are "reconstruction (D-027)"; every check output names
  which kind of rows it used.

## Testing
- Python: `pytest -q` full suite incl. both fingerprint guards; new tests:
  - horizons: H = 6/12/24 frames have t + H ≤ cut-off at every fit/val/test boundary (equality kept); an onset at
    t is not in y(t), one at t + H is; per-H truncation invariance of features and labels-known-at-t of the recent
    rate (labels with s ≤ t − H only) with a negative control per H (a window ending at t);
  - artefact copy: a changed byte in an M6c-1 model file → refuse;
  - test stage: refuses before coverage reaches 10-25; refuses with an overlapping reservation; every check runs
    before `reserve`;
  - red share: hand fixtures (simultaneous red + yellow → red; escalation not counted; N = 0; incomplete coverage;
    strictly-before window), Kyiv City vs Kyivska separate;
  - replay: metrics reproduction (1e-12); row keys equal the M6c-1 eligible test keys (unit, t) exactly; the per-hour
    blend weights equal `reports/m6c1/blend_weights.csv` exactly; and a KEYED per-row comparison: the replay builder
    (`horizons.build_replay`) and an independent recomputation through `pipeline.score_range` on the pinned inputs
    agree per (unit, t) on y, status, p_model, p_baseline, w and p_blend to 1e-12; a fixture that swaps two rows'
    p_model fails it;
  - seam: a row at s = T_seed − 1 h with H = 3 is in the seed as pending and later labelled; no reserved-week label is
    resolved while the flag is absent;
  - issue time: a snapshot written at 10:05 uses (10:05, 10:05 + H] for its label and 10:05 + H ≤ τ for the blend;
  - fit pinning: appending a later version leaves the fit reconstruction identical; editing or deleting a pinned row
    makes the test stage refuse;
  - blend seed: no LABELLED row with s + H > T_seed; every row with s + H > T_seed is present as `pending`; live/seed
    overlap ignored and counted; eviction at 28 d; new version resets.
- Node (`node --test netlify/live/test/`):
  - parity per (type, H) with the Python sample (features, raw, calibrated, baseline, blend) to 1e-9;
  - independent truncation tests in JS per H: alerts after τ removed / ends after τ hidden → identical FEATURE
    VECTORS, MASK STATE and p (not p alone, since a leak can stay inside one tree leaf); mutations per H: a future
    `finished_at`, an alert of exactly 24 h (cap at start + 24 h), purge equality t + H = cut-off, the repeated and the
    skipped DST hour, Kyiv City vs Kyivska, coverage-hole edges; negative control per H: a feature reading an end after
    τ is caught at a pinned τ; the official Aug–Sep 2026 gap regressions (D-022/D-023) still pass;
  - air-raid filter: an artillery alert changes nothing on the new path and still changes the M8 path (D-045 only for
    the new path until the switch);
  - flag absent → `/api/forecast` byte-identical to the pre-M12 golden (`golden_any.json`); flag present → new model;
  - scorer: per-series separation, H = 24 maturity (τ + 24 h + SETTLE), coverage over [τ − 24 h, τ + H], an onset
    exactly at τ + H counted, at τ not; DST; the M8 series unchanged.
- Print shapes, ranges, base rates per stage.
