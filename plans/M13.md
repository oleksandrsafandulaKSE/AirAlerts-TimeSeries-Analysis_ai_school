## 3. The red-share rule live (`netlify/live/lib/kind.mjs`)
- Same definition as `newregime/redshare.py` (D-044): "any" onsets = merged air-raid intervals (D-020 cap); colour =
  red iff a red air-raid alert of the unit starts at that instant (levels as known at τ); escalations not onsets; rule
  at τ = R/N over the unit's onsets with start in (τ − 7 d, τ]; an onset whose level is not yet known at τ is left out
  of R and N and counted in U (observed M = N + U is reported too, so "no alerts" is said only when M = 0); M = 0 → "no alerts in 7 days"; M > 0 = U, N = 0 → "alert kinds not known yet" (no %, never "no alerts"); a unit whose confirmed level coverage does not span
  (τ − 7 d, τ] → "not enough data"; national share = pooled R / N over the onsets of the units WITH full level coverage
  in that window (M12 §C), null with "no national data" when that pool is empty.
- Live knowledge-at-τ (independent of the Python reconstruction): an alert first seen after τ never counts at τ; a
  level that changes later (levels as versions, `levelAt`) is read as known at τ; coverage = `levelCoverage` confirmed
  by τ; unknown ends count as running with the 24 h cap.
- Parity: the JS rule at the τ of every row of `reports/m12/redshare_rows.csv` (τ ≤ 2026-10-18, so no reserved-week
  label) equals Python's R, N, rule and national exactly (fixture = the M12 parity records, known at T_seed).
