# M2 plan v1 — Features known at t + truncation leakage test

Status: APPROVED v1.1 (human decisions 2026-10-12 ~22:45 applied). Implements ROADMAP M2 under CLAUDE.md, D-004, D-013, D-017, D-020, D-021,
on top of M1 (`plans/M1.md` v1.1: half-open intervals, D-020 counting interval
`[start, min(finished_at, start+24h))`, merged unit intervals, approved gap `[2026-08-29, 2026-09-03)`).

## 1. Goal
One feature row per (unit, UTC hour t) on the M1 grid, using only information with timestamp ≤ t,
plus `tests/test_leakage.py`: truncation test on the real raw data with a negative control.
No baselines, no model, no metrics.

## 2. Building blocks (all from M1, all causal)
- **Unit intervals / unit onsets** = `grid.unit_intervals()` (merged D-020 counting intervals;
  onsets = merged starts + uncovered zero-duration starts). Feature onsets are THESE, never raw alert
  starts (post-reform one oblast raid = many raion rows).
- **Onset definition (one rule for labels AND features):** an onset is the start of a merged unit
  interval. D-020's "its start still counts" means a standing alert's start is not dropped; it does not
  mean every constituent start counts (a start while the unit is already under alert is not an onset).
- Causality argument (to be proven by the test, §5): at t, (a) a merged start s ≤ t, and (b) a merged
  end e ≤ t, are the same in full and truncated data, because every counting end ≤ t is either an
  observed `finished_at ≤ t` or `start+24h ≤ t`; ends > t stay > t.

## 3. Features (exact definitions; t = grid hour, UTC)
| Feature | Definition |
|---|---|
| `active_at_t` | from the M1 grid (0 on every unmasked row; kept for audit, NOT in the model list) |
| `minutes_since_last_start` | t − last unit onset with onset ≤ t; NaN if none |
| `minutes_since_last_end` | t − last merged end with end ≤ t; NaN if none |
| `onsets_last_24h` | # unit onsets in (t−24h, t] |
| `onsets_last_7d` | # unit onsets in (t−7d, t] |
| `neighbors_active_at_t` | # neighbours (`regions.NEIGHBOURS`) with `active_at_t == 1` |
| `national_active_count_at_t` | # of the 24 units with `active_at_t == 1` |
| `hour_kyiv`, `weekday_kyiv` | from `t.tz_convert("Europe/Kyiv")`; weekday Mon=0 |
| `unit_code` | index of the unit in the fixed `regions.units()` order (not fitted on data) |

Model feature list (written to `run_meta.json` `features`): all except `active_at_t`.
"Under alert" for neighbours/national = the same D-020 state as the mask (≤ 24h, any level).

## 4. Missing-data rules (NaN, never 0)
Uncertainty zones `U`, from config:
- **Gap zone** `U_gap = [g0, g1 + 24h) = [2026-08-29 00:00, 2026-09-04 00:00)`: inside the gap nothing is
  recorded; for 24h after it, an unrecorded alert could still be counting (D-020), so states, ends and even
  whether a recorded start is an onset are uncertain.
- **History start (decision 1):** no NaN rule. Instead the grid (and train) start moves to
  **2022-03-23 00:00** = first file row (2022-03-15 16:10) + 7 days (longest look-back) with margin for
  the 24h D-020 cap. Amendment to the D-021 train start (2022-03-15 → 2022-03-23); M1 checks and tests re-run.
Rules (applied to the gap zone, all units, since the gap is national):
1. Window counts (`onsets_last_24h`, `onsets_last_7d`): NaN if the window (t−W, t] intersects any U.
   For the gap: t ∈ [g0, g1 + 24h + W).
2. Time-since (`minutes_since_last_start`, `minutes_since_last_end`): NaN if the last event is before the
   end of the gap zone, i.e. if t ≥ g0 and last event < g1 + 24h. "No event at all since the file
   start" is also NaN (no value exists).
3. State features (`active_at_t`, `neighbors_*`, `national_active_count_at_t`): NaN for t ∈ U_gap.
   (Those rows are already masked by `gap_mask`, so this only protects M3 code from reading them.)
4. Calendar and `unit_code`: never NaN.
Every NaN is intentional and counted in the printout. LightGBM handles NaN natively (M4);
baselines in M3 must define their own handling.

## 5. Tests
**tests/test_features.py** (hand-written expectations, toy units A, B, C with A–B, B–C neighbours via an
injected neighbour map):
1. `minutes_since_last_start` / `_end`: alerts `[01:10, 01:50)`, `[03:00, 03:30)` → at 02:00: 50 / 10;
   at 03:00: 0 / 70 (onset at t counts as ≤ t; the interval is active and its end unknown).
2. Standing alert from 00:00 lasting 3 days: at D+1 00:00 → `minutes_since_last_end` = 0 (the cap end is
   known at t); at D 12:00 → NaN (no end ≤ t yet, no earlier history inside the toy → NaN).
3. Onset windows: onsets at t−24h exactly (excluded) and t−24h+1min (included) → `onsets_last_24h` = 1;
   same for 7d. Touching alerts count as one onset; raion inside oblast alert = one onset.
4. Neighbours / national on a 3-unit map: A active, B not, C active → B: neighbors 2;
   A: neighbors 0; national 2 on every unit's row.
5. DST, Kyiv calendar: 2025-03-30 00:00 UTC → hour 2; 01:00 UTC → hour 4 (skipped local 03);
   2025-10-26 00:00 UTC → hour 3; 01:00 UTC → hour 3 (repeated local 03); weekday 6 for all four.
   The UTC grid stays unique and 1h-spaced (from M1).
6. Gap NaN edges (toy gap `[D+1 10:00, D+1 14:00)`, so U = [g0, g1+24h)): (t−24h, t] intersects U iff
   t ∈ [g0, g1+48h). `onsets_last_24h`: t = g0 − 1h → number; t = g0 → NaN; t = g1 + 48h − 1h → NaN;
   t = g1 + 48h → number. Time-since: NaN after g0 until a new event after g1+24h, then a number.
7. Fixed truncation cases (toy, `truncation_check` must return []): touching intervals; an interval that
   a later alert extends after t; `finished_at == t`; `finished_at` = t + 1 min; an alert of exactly 24h;
   t exactly at start + 24h.
8. Join check: `join_to_grid` raises on a duplicated or a missing (unit, t) pair.

**tests/test_leakage.py** (ts-leakage-audit; real data from the M1 cache, `load_official`)
- `truncation_check(feature_fn, alerts, times) -> list[(t, unit, column)]` of mismatches between
  `feature_fn(full)` at t and `feature_fn(truncate(raw, t))` at t, for all 24 units and all columns
  (NaN == NaN counts as equal). Truncation is done on the shared-format alerts after dedup
  (dedup of exact raw rows commutes with truncation): drop `started_at > t`; set `finished_at = NaT` where `> t`.
- Times (fixed, listed in the test, ≈ 25):
  - 5 seeded random hours: 2022, 2023, 2024, 2025 (after the reform), 2026H1;
  - an hour with an active ordinary alert in Kyiv City and one in a frontline oblast (picked from the data
    by a rule: first onset after 2025-06-01, floored to the hour + 1h, asserted active);
  - standing alert: Lypetska hromada (Kharkivska) start 2024-05-12 → start+2h (inside 24h) and start+30h
    (past the cap). Assert `finished_at > t` at both, so the truncated copy hides that end;
  - gap edges: g0 − 1h, g0, g1 − 1h, g1, g1 + 24h − 1h, g1 + 24h, g1 + 48h − 1h, g1 + 48h;
  - DST: 2025-03-30 00:00 and 01:00 UTC, 2025-10-26 00:00 and 01:00 UTC;
  - cut-offs: 2026-06-29 00:00 and 2026-07-27 00:00 (and 1h before each).
- Assert: `truncation_check(real features) == []`.
- **Negative control** (must be caught): two deliberately leaky columns added by a `leaky_features()`
  helper in the test: (a) `current_alert_final_minutes` = for an alert active at t, final
  `finished_at − started_at` (uses an end not known at t); (b) `onsets_centered_3h` = unit onsets in
  (t−90min, t+90min]. **Pinned witnesses:** (a) at (Lypetska start + 2h, kharkivska); (b) at
  (`o.floor("h")`, kyiv_city) where o = the first Kyiv City onset after 2025-06-01 with a non-zero
  minute, i.e. < 1h before a known real onset. Each leaky column is checked at its witness; assert the
  checker reports EXACTLY {(t_a, kharkivska, a), (t_b, kyiv_city, b)}, and that the real features
  report nothing at those same witnesses.
- Runtime target < 60 s (features at ~25 times × 2 builds only, not the full grid).

## 8b. Purge rule (implemented in M3, fixed now)
A training row at t is eligible for a split ending at cut-off C iff `t + H ≤ C` (kept when t+H = C).

## 9. Risks
- Pandas per-time rebuild in the leakage test may be slow → build only the needed units/times.
- A feature could pass the truncation test but still be wrong (truncation proves causality, not
  correctness) → hand tests in test_features.py.
- `onsets_last_7d` NaN after the gap lasts until 2026-09-11, i.e. all test rows after 09-03 have NaN
  for it (test ends 09-07). Acceptable (rows 09-03→09-04 are masked anyway); LightGBM handles NaN.
