# M3 plan v1 — Baselines + evaluation framework (validation only)

Status: APPROVED v1.1 (human decisions 2026-10-13 applied; no second Codex round). Implements ROADMAP M3 under CLAUDE.md, D-006, D-011, D-013, D-021,
D-022 (purge), D-023 (features), D-024 (rows with missing features). Builds on M1 (grid, mask, y)
and M2 (features known at t). The final test is NOT scored in M3 (D-021).

## 1. Goal
Split rules with purge and label maturity, four baselines, the metric suite (incl. the overall
reliability plot), and `reports/official/` output, so that ONE command
(`python scripts/run_all.py --config official`) reproduces the baseline table on validation.
M4 reuses every function here unchanged for the model and the single test scoring.

## 2. Definitions
All intervals half-open UTC `[a, b)` (D-021). H = 1h (config). Splits from `config.official()`:
train `[2022-03-23, 2026-06-29)`, val `[2026-06-29, 2026-07-27)`, test `[2026-07-27, 2026-09-07)`.

- **Eligible row for split S = [a, b)** (`evaluate.eligible(df, split, H)`), all must hold:
  1. `a ≤ t < b`;
  2. purge (D-022): `t + H ≤ b` (kept when t+H equals the cut-off). An onset exactly at the test start C
     is in no test LABEL: test row t = C has label window (C, C+1h], and an onset at C only masks row C.
     So validation reads no test label (test: §6 "boundary onset");
  3. `mask == 0` (not under alert, not gap-masked) and `y` not NaN;
  4. every model feature in `features.FEATURES` is not NaN (D-024).
  Exclusions are printed per split twice: EXCLUSIVE counts (first failing reason in the order purge →
  masked → y NaN → feature NaN; they sum to the excluded total) and OVERLAPPING counts per reason.
  With H = 1 on an hourly grid, rule 2 removes nothing; it is tested with H = 3.
- **Gap intervals (explicit, in config, asserted on the real grid):** target/state mask
  `[2026-08-28 23:00, 2026-09-04 00:00)` = 1h before the gap (its label window touches it) + the gap
  `[08-29, 09-03)` + 24h after it = 145 h; state uncertainty zone `[2026-08-29, 2026-09-04)`;
  look-back NaN rules as in D-023.
- **Test-label isolation:** the frame passed to the M3 stage has `y = NaN` for every row with
  t ≥ test start (asserted before any baseline runs). The `allow_test` guard stays.
- **Label known at t:** the label of row s is known once `s + H ≤ t`. Any statistic used at t may
  read labels only of rows with `s ≤ t − H`.
- **Fit set** for the frozen baselines (climatology, calibrated persistence) = eligible TRAIN rows.
  Nothing is ever fitted on validation or test rows.
- **Scoring set** in M3 = eligible VALIDATION rows. All four baselines are scored on exactly the same
  rows (asserted). `score(..., split="test")` raises unless `allow_test=True`; nothing in M3 passes it.

## 3. Baselines (`src/baselines.py`); each returns one probability per scoring row
1. **Climatology** (frozen, train): per unit × Kyiv hour × Kyiv weekday cell,
   `p = (k_cell + α·p_unit) / (n_cell + α)` with `p_unit` = unit's train onset rate, α = 10
   (pseudo-rows). Uses `hour_kyiv`, `weekday_kyiv` from M2.
2. **Recent rate** (ROLLING, D-021): for unit u at t, over history rows s of u with
   `t − 14d ≤ s ≤ t − H`, `mask(s) == 0`, `y(s)` not NaN:
   **`p = (k + 10·p_unit) / (n + 10)` for every row** (human decision, option B; amends D-021/CLAUDE.md:
   pure k/n on ~10 rows gives 0/1 rates and makes the primary comparator artificially weak).
   n stats (min / median / count of n < 10 / n == 0) are printed.
   History rows are NOT required to have all features (D-024 is about the row being scored, not about
   labels used as history). Evidence for option B: Dnipropetrovska has only 14 unmasked rows in the
   6 weeks from 2026-06-15 to 07-27. Implementation: per unit, cumulative sums of
   (eligible label, 1) on the hourly grid and two `searchsorted` lookups, so it is exact and O(n).
3. **Raw persistence**: `p = 1` if a unit onset lies in `(t − H, t]`, else 0, from `grid.unit_intervals`
   merged onsets (D-023), the same onsets as labels and features. On unmasked rows this means "an alert started and already ended in the last hour".
4. **Calibrated persistence** (frozen, train): state = bin of `minutes_since_last_end`:
   `[0, 60)`, `[60, 180)`, `[180, 720)`, `[720, ∞)`. Per unit × bin:
   `p = (k + α·p_unit) / (n + α)`, α = 10.
The unit train rates `p_unit` are computed once from the fit set and printed.

## 4. Metrics (`src/evaluate.py`), per baseline, overall and per group (Kyiv City / frontline / rear, D-011)
- **Brier** = mean (p − y)².
- **Brier skill vs recent rate** (PRIMARY, D-021) = 1 − Brier / Brier_recent, on the same rows.
  (Recent rate's own skill is 0 by definition.)
- **ROC-AUC pooled** (`sklearn.metrics.roc_auc_score`); NaN with a printed reason if one class is absent.
- **Mean within-unit ROC-AUC**: AUC per unit, averaged over units with ≥ 10 positives AND ≥ 10 negatives
  in that set; the number of units excluded is reported next to it.
- **PR-AUC** = average precision (`average_precision_score`), and **PR-AUC / base rate**.
- **Base rate** and **row count** of the set, printed next to every metric row.
- **Reliability plot (overall, required, D-006)**: one figure, all four baselines, 10 fixed-width bins
  `[0, 0.1), …, [0.9, 1.0]`; point = (mean p, mean y) per non-empty bin, marker size ∝ count; diagonal line.
  Fixed width (not quantile) because raw persistence has only two values. Per-bin counts saved to CSV.
Zero denominators (Brier_recent = 0, base rate = 0, one class absent, empty group, unit without train
rows): the metric is NaN and the reason is printed and saved; no silent fallback.
Output (approved D-017 exception: `metrics_validation.*` in M3, `metrics.*` reserved for M4; no new
dependencies): `reports/official/metrics_validation.csv` and `.json` (baseline × group rows),
`reliability_validation.png`, `reliability_validation_bins.csv`, `m3_checks.json` (eligibility counts,
`p_unit`, recent-rate history n stats); `run_meta.json` gains `m3: {split: "val", baselines: [...]}`.
`metrics.csv` / `metrics.json` (the headline names in D-017) are reserved for the M4 test scoring.

## 5. Steps
1. `evaluate.eligible()` + exclusion counts + the test guard (15 min).
2. `baselines.py`: four baselines with a common signature
   `predict(grid_with_features, fit_rows, score_rows, cfg) -> np.ndarray` (35 min).
3. `evaluate.py`: metrics, group table, reliability plot (matplotlib Agg) (25 min).
4. `run_all.py`: M3 stage after M2; writes everything only after all checks pass (10 min).
5. Tests (30 min), `pytest -q`, reviewer, harness review (fresh subagent), fixes.

## 6. Tests (expected values written by hand)
**test_evaluate.py**
- Eligibility on a toy grid, H = 3, cut-off C = val start: rows t = C − 3h kept, C − 2h and C − 1h purged;
  with H = 1, row C − 1h kept. Masked row, NaN-y row, NaN-feature row each excluded with the right reason;
  printed counts equal the hand counts.
- `score(split="test")` raises without `allow_test=True`.
- Brier: p = [0.2, 0.8], y = [0, 1] → 0.04. Skill: Brier 0.04 vs reference 0.08 → 0.5.
- AUC: perfect ranking → 1.0, reversed → 0.0, one class only → NaN + reason.
- Average precision: y = [1, 0, 1], p = [0.9, 0.8, 0.7] → (1 + 2/3) / 2 = 0.8333.
- Within-unit AUC: unit with 9 positives is excluded and counted; mean over the others matches hand value.
- Reliability bins: p = [0.05, 0.05, 0.95], y = [0, 1, 1] → bin [0, 0.1): mean p 0.05, mean y 0.5, n 2;
  bin [0.9, 1.0]: (0.95, 1.0, 1); p = 1.0 falls in the last bin.
- Group table has exactly the rows overall / kyiv_city / frontline / rear; all baselines are scored on
  identical (unit, t) keys (asserted, not just counts).
- Zero denominators: reference Brier 0 → skill NaN + reason; base rate 0 → PR-AUC/base NaN + reason;
  empty group → NaN row + reason.
- Boundary onset: toy grid with an onset exactly at C = test start → last validation row (C − 1h) has
  y = 1 and is eligible; test row C is masked; after isolation every y with t ≥ C is NaN and the M3
  stage reads none of them.
- Isolation: `isolate_test_labels` sets y NaN exactly on t ≥ test start and leaves earlier rows unchanged.
- Gap intervals: config values equal the literals above; on the real grid, rows 08-28 22:00 → gap_mask 0,
  08-28 23:00 → 1, 09-03 23:00 → 1, 09-04 00:00 → 0 (all units).

**test_baselines.py**
- Recent rate on a toy unit, H = 1: hand-placed labels; at t the window is `[t − 14d, t − 1h]`;
  a positive at s = t − 1h counts, s = t does not, s = t − 14d counts, s = t − 14d − 1h does not;
  masked and NaN-y history rows are excluded from n.
- Recent-rate causality: change every label with s > t − H (including the scored row itself) → p at t unchanged;
  change one label at s = t − H → p changes (negative control for the check).
- Shrinkage: k = 2, n = 10, p_unit = 0.1 → (2 + 1)/(20) = 0.15; n = 0 → p_unit.

**test_leakage.py (extended)**: the raw-data `truncation_check` runs on recent rate and raw persistence at
~6 real times (val start, mid-validation, the val/test cut-off and the hour before it, two gap edges),
with p_unit frozen from train. Negative control: a recent rate whose window reaches s ≤ t (reads the
unknown label of row t) must be caught at a pinned witness.
- Climatology: toy fit set with known cell counts → `(k + 10·p_unit)/(n + 10)` by hand; changing any
  validation/test label leaves all climatology predictions unchanged.
- Calibrated persistence: bin edges (59.9 → bin 0, 60 → bin 1, 720 → bin 3) and the shrinkage formula by hand;
  fit uses train rows only (same perturbation check).
- Raw persistence: onset at t − 30 min → 1; onset exactly at t − H → 0 (outside (t−H, t]); onset at t → 1.

**test_run_all.py**: on the existing fixture, the M3 stage writes `metrics_validation.csv` with
4 baselines × 4 groups, the PNG and `m3_checks.json`; and no file contains test-period metrics.
