# M4 plan v1 — Models (H = 1, H = 3) + the single final-test scoring + new-regime section

Status: AGREED (consensus round 5, D-026; D-027 applied; history_start corrected). See reviews/M4-consensus.md. Human decisions already given in chat
(2026-10-13): one model per horizon ("option 1") → train an H = 1 model (headline) and an H = 3 model
(extra results row); the new-regime section stays H = 1 (M3b provisional decision).
Rules: CLAUDE.md, D-005, D-006, D-007, D-011, D-013, D-015 (amended by D-021), D-017, D-020–D-025, M3b plan.

## 1. Goal
1. Train one pooled LightGBM model per horizon on eligible TRAIN rows, early-stopped on VALIDATION,
   no refit (D-021); check calibration on validation and apply a pre-registered calibration rule.
2. Pre-register everything, then score the FINAL TEST (2026-07-27 → 2026-09-07) **once**, for the model and
   all four baselines together, overall and per group, for H = 1 (headline) and H = 3 (extra row).
3. New-regime section (D-015, exploratory, H = 1): API loader, before/after table, frozen H = 1 model and
   baselines scored on "any alert starts", within-unit AUC and calibration-in-the-large per group.
No training or tuning on API data. Official and API data never share a training set or a metric.

## 2. Model (`src/model.py`)
- Library: `lightgbm` (already pinned 4.7.0; no new dependency). Objective `binary`.
- Features: exactly `features.FEATURES` (D-023); `unit_code` passed as a categorical feature (codes are the fixed
  `regions.units()` order, not fitted on data). NaN never reaches the model (D-024 eligibility).
- Params (fixed, no search, D-013): learning_rate 0.05, num_leaves 31, min_data_in_leaf 100,
  feature_fraction 1.0, bagging off, `seed` 20261013, `deterministic=True`, `num_threads=1`, max 2,000 rounds,
  early stopping 100 rounds on pooled validation `binary_logloss`.
- Fit set = eligible train rows (M3 `eligibility`, purge t + H ≤ train end, D-024 feature rule).
  Early-stopping set = eligible validation rows (purge t + H ≤ val end). Test rows never enter `lgb.Dataset`.
- No refit on train + validation (D-021). The model is saved as `reports/<run>/model.txt` + its sha256.
- Printed: rows used, best iteration, validation logloss curve (saved to `model_curve.csv`), feature importance (gain).
- Early-stopping noise (reviewer M3 question): the validation logloss at the best iteration and at ±100 rounds
  is printed, so a flat curve is visible; no further tuning.

## 3. Calibration (validation only, pre-registered)
- ECE on validation = Σ_bins (n_b / N)·|mean_p_b − mean_y_b| over the 10 fixed-width bins of `evaluate.reliability_bins`.
- Calibration-in-the-large on validation = mean p − mean y.
- **Rule, fixed before the test:** if validation ECE ≤ 0.02, the headline model is the raw model and no calibrator
  exists (only the raw row is reported). If ECE > 0.02, fit Platt scaling on the eligible validation rows of THIS
  model and the headline model is "raw model → Platt" (D-021); both the raw and the Platt row are then reported.
- Platt details: x = logit(clip(p, 1e-6, 1 − 1e-6)); `sklearn.linear_model.LogisticRegression(penalty=None,
  fit_intercept=True, solver="lbfgs", max_iter=1000)`; raise if it does not converge, if validation has one class,
  or if the slope ≤ 0. Saved as `calibrator.json` {decision, ece, slope, intercept, clip}.
- Note: if Platt is fitted, the validation metrics of the calibrated model are in-sample for the calibrator; this
  is labelled in the table.

## 4. Pre-registration and the single final-test scoring
- Two stages: `run_all.py --config <run> --stage fit` (M1–M3 + model + calibration + pre-registration; reads NO test
  label) and `run_all.py --stage final-test` (scores BOTH horizons in one call). The final-test stage refuses to run
  unless `reports/official/preregistration.json` AND `reports/official_h3/preregistration.json` both exist, so
  neither horizon's test result can be seen before both predictors are frozen (M3b, D-021).
- `preregistration.json` (per run) records: config + dates, H, feature list, LightGBM params, best iteration, sha256 of
  `model.txt`, of `calibrator.json` (decision + Platt coefficients, or "none"), of `baseline_fit.json` (`p_unit`,
  climatology cells, persistence cells), of the official data file, and a code fingerprint (sha256 over `src/*.py` +
  `scripts/run_all.py`); eligibility rule, metric list, primary metric (Brier skill vs rolling recent rate).
- `score_final_test(...)` is the ONLY caller of `evaluate.split_bounds(cfg, "test", allow_test=True)`. Before reading
  any test label it (1) recomputes every sha256 above from the files it will actually use and the current code, and
  raises on any mismatch, for BOTH horizons, before touching either horizon's labels; (2) writes ONE joint marker
  `reports/final_test_access.json` {timestamp, sha256 of official/preregistration.json, sha256 of
  official_h3/preregistration.json} BEFORE any test label of either horizon is read. If the joint marker exists and
  either sha256 differs → raise (so a crash after scoring H = 1 cannot allow replacing H = 3's predictor). Same pair
  of sha256 → allowed (exact reproduction; metrics must then be identical).
- The predictor used on the test is rebuilt ONLY from the frozen files (`model.txt` → raw p → calibrator.json), and
  must reproduce the saved validation predictions exactly before scoring (assert).
- Test eligibility = M3 rules with the test split: in range, t + H ≤ test end, unmasked, label known, all features
  known (D-024). Exclusions printed exclusive + overlapping (H = 1 expected: 13,116 eligible rows).
- Predictions on test rows:
  - model (+ Platt if pre-registered); frozen climatology / calibrated persistence / `p_unit` from train;
  - recent rate ROLLING through the test (D-021): history = rows s ≤ t − H with known labels — inside the test this
    reads earlier TEST labels, which is allowed (they are in the past at t);
  - raw persistence from the merged onsets.
  All five on identical (unit, t) keys (asserted).
- Outputs (D-017 names): `reports/<run>/metrics.csv` + `metrics.json` (model + 4 baselines × overall/kyiv_city/
  frontline/rear: rows, base rate, Brier, **Brier skill vs recent rate (PRIMARY)**, pooled ROC-AUC, mean
  within-unit ROC-AUC with units used/excluded, PR-AUC, PR-AUC / base rate), `reliability.png` (overall, all five,
  REQUIRED, D-006), `reliability_bins.csv`, `calibration_in_the_large.csv` (per group).
- Reporting rules from D-025: within-unit AUC printed next to pooled AUC; pooled AUC is never called "the ranking
  result"; groups with < 100 eligible rows or units excluded from within-unit AUC are flagged "low-n".
- Not beating recent rate is a valid, reportable result (D-021).

## 5. New-regime section (D-015, exploratory, H = 1) — `--config new_regime`
### 5.1 `data.load_api(dump_dir)` → shared format (D-017 #2)
- Input: `data/raw/alerts_in_ua/2026-10-12T1645Z/` (`manifest.tsv` + `uid_<n>.json`). The UNIT of an alert is the
  file's requested UID (checked: every file names exactly one `location_oblast`; `location_oblast_uid` holds raion
  ids and is NOT used). UID → unit only via `regions.py` api_uid. Identity check: `regions.py` gains the API's
  Ukrainian oblast name per unit (e.g. kyiv_city "м. Київ", kyivska "Київська область"); every file's single
  `location_oblast` must equal the name of the unit its UID maps to, else raise (a swapped 31/14 file is caught).
- Raising checks: manifest lists 3–31; HTTP 404 exactly for 6 and 7 (empty files); every 200 file parses; each
  file has one `location_oblast`; excluded UIDs 16 (Luhanska), 29 (Crimea), 30 (Sevastopol) dropped with counts;
  the 24 canonical units present; `alert_type` values printed (only `air_raid` kept; others counted and raise if
  present, since the target is air-raid alerts).
- Dedup by `id` keeping the latest `updated_at`; **open alerts are KEPT** (D-027, human decision after the round-2
  escalation): `finished_at` = NaT means "end unknown" and the D-020 24h cap applies, exactly like truncated official
  alerts. Counts printed: open alerts per unit, and how many started inside the window (10 starting in [history_start, grid_end) in this dump — implementation count, harness review;
  12 if counted up to coverage_end). No missing-data zones are created for them. `level` = `location_type` (oblast / raion / hromada / city);
  `alert_level` = yellow / red; times parsed as UTC (`Z` suffix required, else raise); `source = "api"`.
- The D-020 24h cap and the merged-union logic are reused unchanged (`grid.unit_intervals`).
### 5.2 Config `new_regime`
- `history_start` (corrected during implementation, consensus round 5): `month_ago` returns alerts that FINISHED (or
  are still open) after `fetched_at − 30 days` of that file — verified on every file: the earliest `finished_at` is
  ≥ its cutoff (closest margin 3.3 min), and closed alerts that started before the cutoff (42 before their own file's
  cutoff, 50 before the common cutoff below; Codex round 5 recount) appear only because they ended late (survivorship). Coverage is complete only for alerts STARTING at or after the cutoff, so
  `history_start` = max over the 24 units' files of (`fetched_at` − 30 days) = **2026-09-12 17:00:43** (fixed in config,
  asserted against the manifest; the plan's earlier "earliest closed start" formula gave 2026-09-11 05:50, which is
  wrong). Alerts that started before `history_start` (closed or open) are kept for interval construction; the
  history-start uncertainty zone `[−∞, history_start + 24h)` masks state and labels and makes windows/time-since NaN
  exactly as before, so their incompleteness cannot reach a scored row. Grid `[2026-09-13 00:00, 2026-10-12 16:00)`; `coverage_end` = earliest `fetched_at`
  in the manifest (2026-10-12 16:45:36); H = 1; `target_levels = "any"`; no approved gaps. Gap detection runs only on alerts
  that START inside the API coverage window `[history_start, coverage_end)` (older open alerts are kept for interval
  construction but excluded from gap detection, which would otherwise see a 2024 → 2026 "gap"); it must find none, else
  raise. `grid.detect_gaps` gains an explicit `[start, end)` range argument (official keeps its current full range);
  regression fixture: an old open alert + a dense recent window → no gap detected within the range, and the
  out-of-range silence is ignored.
- Uncertainty before the history start: zone `[−∞, history_start + 24h)` handled exactly like the post-gap zone
  of D-023 (state features NaN; windows touching it NaN; time-since NaN if the last event is before its end), so
  the D-024 rule removes the warm-up rows (7-day window → first scored row ≈ 2026-09-20 17:00). Row counts printed.
### 5.3 Analyses (`reports/new_regime/`)
- (a) `before_after.csv` per unit and group, computed AFTER the final test is scored (the official window is inside
  the test period). Exposure = grid hours in the window that are NOT in any uncertainty zone (official: the gap
  zone; API: the history-start zone only — open alerts create no zones, D-027); unknown exposure is excluded, never
  counted as quiet.
  onsets per 30 days = (# merged unit onsets (D-023) with start in an exposed hour) / (exposed hours / 720);
  share under alert = (# exposed hours with active_at_t = 1, D-020 state) / exposed hours. Groups: pooled sums
  (onsets summed / exposed unit-hours summed; active hours summed / exposed unit-hours summed). Windows: official
  [2026-07-27, 2026-08-29), API [2026-09-13, 2026-10-12 16:00).
- (b) the frozen H = 1 headline PREDICTOR — `model.txt` + `calibrator.json` (logit, clip, Platt) — loaded from
  `reports/official/`, every sha256 checked against `reports/official/preregistration.json`, and required to
  reproduce the saved official validation predictions exactly before any API row is scored; + the four baselines
  on API eligible rows, target "any alert starts",
  mask "any level active". Frozen tables (`p_unit`, climatology, persistence cells) loaded from
  `reports/official/baseline_fit.json`; recent rate rolling on API labels; raw persistence from API onsets.
  Same metric suite → `metrics.csv`. Red-only row: NOT in this plan (optional, D-015).
- (c) per group: mean within-unit AUC + calibration-in-the-large (mean predicted vs observed) → `transfer.csv`.
- A run with `--config new_regime` raises if any alert in its frame has `source != "api"`; the official runs raise on
  `source != "official"` (never mix).
- (d) README conclusion: M5, conditional on (b)/(c).

## 7. Tests (hand-written expectations)
- `test_model.py`: deterministic training (two fits → identical model text); exact keys: the fit dataset's (unit, t)
  keys == eligible train keys and the early-stopping keys == eligible validation keys, for H = 1 and H = 3, with the
  purge boundary rows (C − H kept, C − H + 1h dropped) checked by hand; behavioural isolation: flipping every label
  with t + H > val end (incl. purged rows and the whole test) leaves the model text identical; flipping validation
  labels changes `best_iteration` but leaves the fit keys identical; no refit (saved model = early-stopped model);
  ECE and calibration-in-the-large on hand cases (p = [0.05, 0.05, 0.95], y = [0, 1, 1] → ECE = (2/3)·0.45 +
  (1/3)·0.05 = 0.3167); Platt applied only when ECE > 0.02 (both branches); unit_code categorical.
- `test_final_test.py`: `score_final_test` refuses without `preregistration.json`; a second call with a different
  preregistration sha256 raises; the same sha256 reproduces identical metrics; only `score_final_test` passes
  `allow_test=True` (grep-style test over `src/` and `scripts/`); all five predictors on identical keys; recent rate
  inside the test reads only s ≤ t − H (label-perturbation test at a test time on a toy frame).
- `test_api_loader.py` (JSON fixtures): duplicate id keeps latest `updated_at`; an open alert is KEPT with
  `finished_at` = NaT and counted (D-027), and in the grid it masks exactly [start, start + 24h) and its start is an
  onset (causal cap, hand-checked);
  unknown UID file raises; 16/29/30 dropped; a file naming two oblasts raises; missing `Z` raises; non-air_raid raises;
  output columns/order = shared format, `source = "api"`, `alert_level` kept; 23 units → raises.
- `test_new_regime.py`: before/after on a toy official + toy API frame (onsets/30d and share by hand);
  calibration-in-the-large by hand; the new-regime stage raises on a mixed-source frame; frozen model hash mismatch raises;
  history-start uncertainty zone: rows inside it have NaN state/window features (hand edges).
- Leakage: `test_leakage.py` adds (1) a truncation check of a small model's predictions (trained on a sample, saved)
  at 4 real official times; (2) an API loader-to-predictor truncation check: truncate the RAW API alerts at t (drop
  starts > t, hide ends > t) → loader → grid → features → predictor at 4 API times (one inside a >24h alert's first
  24h, one right after a cap, one inside the first 24h of an alert still open in the dump), comparing EVERY feature
  column, the D-024 eligibility status and the prediction with the full-dump values; negative control:
  a predictor fed the final alert duration is caught. DST/gap/rolling-window checks stay as in M2/M3 (the API window
  has no DST change and no recording gap).

## 10. Risks
- Few eligible frontline validation rows (33–83 per unit, D-025) → noisy early stopping; pooled logloss is used.
- Platt fitted on 11k validation rows could be unstable for H = 3 (base rate 0.24) — the rule is pre-registered either way.
- API: month_ago covers ~30 days; units with few alerts may have NaN time-since features for long → D-024 removes rows;
  counts printed per unit.
- Model file size in `reports/` (committed by the human) — expected < 1 MB.

## 11. Decisions (round 1)
1. LightGBM params as listed, no search — PROVISIONAL.

3. New-regime grid end 2026-10-12 16:00 (coverage_end from the manifest) — PROVISIONAL.
