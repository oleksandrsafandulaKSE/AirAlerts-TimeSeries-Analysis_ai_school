## 1. Goal
Communicate the finished results honestly: a complete README, figures generated from saved results, and a static
results site that can be hosted on Netlify. Every number and figure comes from a `reports/<run>/` file written by
`scripts/run_all.py` (ROADMAP M5 done-criterion). No new modelling, no re-scoring, no new metric on the test.

## 2. Hard constraint from M4: the code fingerprint
After the final test is scored, `src/*.py` and `scripts/run_all.py` MUST NOT change: the pre-registration stores their
sha256 and an exact reproduction run must keep passing (`score_final_test` refuses otherwise). Therefore all M5 code
lives OUTSIDE that fingerprint and only READS `reports/`:
- `scripts/build_site.py` — reads `reports/official`, `reports/official_h3`, `reports/new_regime`; writes `site/`
  (one self-contained HTML page with the data embedded) and the README's GENERATED blocks. It never imports pipeline
  code that fits or scores, never reads `data/`, and never recomputes a metric: it only copies/reshapes values from the
  saved CSV/JSON files, addressing every value by its exact source key (file, predictor, group, metric).
- `app/streamlit_app.py` — REQUIRED (ROADMAP M5, D-012), reads only `reports/` (§6).
- README edits (hand-written prose + generated blocks).

## 3. Site (`site/`, Netlify-ready)
- One static, self-contained page `site/index.html` with the data embedded as an inline JSON block (works from a
  file URL with no fetch), + `netlify.toml` at the repo root (`publish = "site"`, no build command: pre-built).
- Libraries: none — inline SVG + vanilla JS only. No tracking, no external fonts, no network request at all: the page
  works fully offline from a file URL.
- Sections (all values read from the embedded JSON; an undefined metric is JSON `null` and is shown as "n/a" with its
  saved reason, never as a number and never interpreted as "not better"; low-n flags, AUC units used/excluded shown):
  1. **Headline**: final-test Brier skill of the model vs the rolling recent-rate baseline (H = 1), with the base rate,
     row count and the plain-language reading ("better / not better than the recent rate"). If the model does not beat
     recent rate, the headline says so (D-021).
  2. **Final-test table, H = 1 and H = 3 (tabs)**: model + 4 baselines × overall / Kyiv City / frontline / rear: Brier,
     Brier skill, pooled AUC NEXT TO within-unit AUC (D-025: pooled AUC is never presented as the ranking result),
     PR-AUC and PR-AUC/base rate, low-n flags shown. H = 3 labelled "additional horizon, not comparable to H = 1".
  3. **Reliability diagram** (required, D-006): final test, overall, model + baselines, from `reliability_bins.csv`;
     point size = bin count.
  4. **Validation vs test**: the same headline numbers on validation (honest view of what was known before scoring).
  5. **New alert system (exploratory, D-015)**: before/after table (onsets per 30 days, share of time under alert) per
     group and unit; transfer table (within-unit AUC, calibration-in-the-large). Measured differences stated as facts;
     interpretations labelled as hypotheses; the conclusion is CONDITIONAL on the transfer numbers (D-015 d).
  6. **Method & no-leakage**: precise text — target = a merged-unit onset (D-023) in (t, t+H] (an onset exactly at t is
     not in y(t); one at t+H is); mask = a non-standing alert active at t (D-020 24h cap); splits half-open, purge keeps a
     row iff t + H ≤ cut-off; recent rate over unmasked rows with known labels in [t − 14d, t − H], shrunk toward the
     unit's train rate (α = 10, D-025); calibrated persistence = unit × `minutes_since_last_end` bins [0,60), [60,180),
     [180,720), [720,∞) (this is how "state at t" is implemented); pre-registration + the single joint scoring.
     Data issues: duplicates; the DETECTED gap [29 Aug 05:00, 2 Sep 13:00) vs the APPROVED gap [29 Aug, 3 Sep) and
     the masked envelope [28 Aug 23:00, 4 Sep 00:00) for H = 1 ([28 Aug 21:00, …) for H = 3) and the feature-uncertainty
     zone; per-horizon test eligible/excluded counts from `final_test_checks.json` (the nominal "six weeks" has
     missing coverage, shown explicitly); open API alerts (D-027).
     **Leakage evidence table** (ts-leakage-audit format: check | PASS/FAIL | evidence): filled from an actual
     `pytest` run of the named tests (truncation on real data incl. DST, gap edges, unknown future ends, >24h standing
     alerts, cut-offs, API loader path; each negative control caught). Wording: "tested at these times/cases", not
     "proven for all t".
  7. **Limitations** (from README).
- Design: responsive (phone width, 16 px gutters, no horizontal scroll), light + dark via `prefers-color-scheme`,
  accessible colours (colour-blind-safe palette, text labels on charts), title "Air-raid alert onset forecasts".
- Wording: no claim beyond the saved numbers; "exploratory" on every new-regime element.

## 4. Figures
README figures are ONLY the PNGs written by `scripts/run_all.py` (ROADMAP M5): `reports/official/reliability.png`,
`reports/official_h3/reliability.png`, `reports/new_regime/reliability.png`, validation reliability plots. The site's
charts are rendered in the browser from the same saved CSV values (no new figure files, no recomputation).

## 5. README
Fill every section from the saved files: framing, data (admin reform, freeze, duplicates, recording gap, standing
alerts, open API alerts), method, no-leakage guarantee (with the pre-registration and joint-marker story), results
(H = 1 headline table, H = 3 extra table, reliability plot), new regime (exploratory, conditional conclusion),
limitations (incl. low-n frontline, unit-level outages, H = 3 caveats, recent rate drops 2 freshest hours at H = 3,
early-stopping noise, the M3b/M4 plan corrections), how to run (fit → final-test → new_regime → build_site), status.
All result NUMBERS in the README live in GENERATED blocks (`<!-- GENERATED:<name> START/END -->`) written by
`build_site.py` from exact source keys; hand-written prose carries no result numbers (it may say "see the table").

## 6. Streamlit (required)
`app/streamlit_app.py` (REQUIRED) reads only `reports/` files and shows the same tables, the reliability plots and
the new-regime tables; a smoke test imports it and checks its loader finds every file it expects. Netlify cannot run
Streamlit, so the hosted deliverable is the static site; Streamlit is for local use (`streamlit run app/streamlit_app.py`).

## 7. Hosting
- `netlify.toml` + pre-built `site/`. Deploy command: `npx netlify-cli deploy --dir site --prod`.
- The Netlify CLI on this machine is NOT logged in, and logging in needs the human's credentials, which the builder
  must not enter. So the builder prepares the site and the exact command; the human deploys (one command) or links the
  repo in the Netlify UI. As an immediately viewable preview, the same page is published privately to the human's
  claude.ai artifacts (private by default; not public).

## 8. Tests
- `tests/test_site.py` (on fixture report folders): every cell of the embedded JSON equals the value at its exact
  source key (file, predictor, group, metric); MUTATION checks fail: swapping two predictors, two groups, H = 1/H = 3,
  or two metric columns in the source must change the output at those keys; NaN → null with reason; the build raises if
  any required report file is missing (no placeholders); the README's generated blocks equal a fresh regeneration
  (exact text) AND are verified INDEPENDENTLY: the test parses each generated README table into (row label, column
  label, value) cells and checks every cell against the source file at the key named by its labels (predictor, group,
  horizon, metric), so a consistently mislabelled README fails; the swap mutations above are applied to the README path
  too. Hand-written README sections contain no result numbers in ANY format: every number token (integer of any size,
  decimal, percentage) outside the generated blocks must match an explicit allow-list kept in the test — calendar
  dates/times/years, D-numbers, milestone ids, version pins, and rule constants (H = 1/3, 24h cap, 14-day window,
  7-day window, α = 10, ECE threshold 0.02, 30 days, 10 pos/neg, 100 rows, 6 weeks, 24 units, 23 oblasts, 15 rear,
  8 frontline); mutations inserting result-like phrases ("0 units used", "1 positive", "7 positives", "9 rows") into
  hand-written text must make the test fail;
  group mapping: Kyiv City alone, Kyivska in rear, frontline = the D-011 list (checked against `regions.py`).
- HTML smoke check: the page parses its EMBEDDED JSON payload (no `data.json`, no fetch) and renders all sections,
  opened from a `file://` URL and over http (headless check in the built-in browser:
  no console errors; phone width without horizontal scroll).
