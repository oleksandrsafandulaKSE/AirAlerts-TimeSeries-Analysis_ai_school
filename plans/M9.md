## B. Uncertainty on the gain vs recent-rate (D-013)
- **Rows:** scored rows only (`status == "scored"`). Per-row loss difference d = (p_model − y)² − (p_rr − y)².
- **B1. Block bootstrap of BSS = 1 − ΣBrier_model / ΣBrier_rr**, recomputed as a ratio on each resample. Never
  average per-row or per-unit skill.
  - **Blocks** are calendar units in UTC. A block = all scored rows whose t falls in it, all units together.
    Rows are never invented for unit-hours that weren't scored.
  - **Primary (D-013 wording): week blocks.** Weeks are Monday 00:00 UTC. Partial weeks are kept as blocks with
    their real rows; there is no reweighting.
  - **Sensitivity: day blocks.** Resampling draws K blocks with replacement, uniformly, where K = the number of
    blocks. The resample length varies with the rows per block, and BSS is recomputed on the pooled rows.
  - **Sensitivity: 24 h circular moving blocks** over the ordered list of distinct scored hours. Start
    uniformly over that list, wrap from the last hour to the first, and concatenate ceil(n_hours/24) blocks
    truncated to n_hours. Each hour brings all its scored rows.
  - If a resample has ΣBrier_rr == 0, raise. Never skip.
  - B = 10,000 resamples, seed fixed at 20261017, percentile 95% CI.
  - Report the number of blocks: test has 5 week blocks, and the README says that the week-block interval is
    coarse.
- **B2. Diebold–Mariano-style test, row-weighted** (the same estimand as BSS's numerator).
  - Per scored hour h, S_h = Σ d over its rows. The statistic is z = ΣS_h / sqrt(N_h · V̂), where V̂ is the
    Newey–West long-run variance of the S_h series (Bartlett kernel, lags 24 and 72), so ΣS_h / N_rows is the
    row-weighted mean difference.
  - Report z and two-sided p. Also report the iid row-level z for contrast, labelled "ignores clustering, too
    optimistic".
- **B3. The same for validation** (V0 `p_headline` vs `recent_rate`).
  - Join on (unit, t) with UTC-aware timestamps. Assert unique keys in both files and identical key sets.
  - Assert identical `y` in both files (both have a `y` column), to the bit.
  - Groups come from `regions.group_of(unit)`, never from names, so Kyiv City and Kyivska stay separate.
  - Any mismatch raises. Validation has 4 week blocks.
- **B4. Tests:**
  - a synthetic case where model = recent-rate gives a CI that contains 0, with BSS exactly 0;
  - a strictly better model gives a CI above 0;
  - the block resampler keeps all units of a block together;
  - a fixed seed reproduces the result;
  - BSS on the full sample equals `reports/official/metrics.csv` overall (−0.0101) to 1e-12.

## C. CORP reliability and Brier decomposition (D-006 upgrade, addition only)
- **C1. `extras/corp.py`:** PAV recalibration with `IsotonicRegression(increasing=True, out_of_bounds="clip")`.
  - Fitted on (p, y) of the SAME rows it describes. This is a diagnostic only, and the recalibrated values are
    never used as forecasts (stated in the plot caption).
  - Decomposition: Brier = MCB − DSC + UNC, with MCB = B(p) − B(p_pav), DSC = B(ȳ) − B(p_pav), UNC = B(ȳ).
    Assert that the identity holds to 1e-12.
- **C2. Plots:** `reports/extras/corp_validation.png`, `corp_test_posthoc.png`. Each shows model and
  recent-rate, the diagonal, and a 90% band from the week-block bootstrap of the PAV curve (the same resamples
  as B1).
  - The x-axis is clipped to the 99.5th percentile of p, with the share of rows beyond it printed.
  - The existing fixed-bin plots (`reports/official/reliability*.png`) stay as they are.
- **C3. Table `reports/extras/corp.csv`:** split × {overall, kyiv_city, frontline, rear} × {model, recent_rate}
  → Brier, MCB, DSC, UNC. On identical rows, BSS = [(DSC_m − DSC_r) − (MCB_m − MCB_r)] / B_r, and a test
  asserts this matches B1's full-sample BSS.
- **C4. Tests:**
  - **A hand-calculated miscalibrated fixture,** so that returning the unchanged p would fail.
    p = [0.1, 0.2, 0.3, 0.4], y = [0, 1, 0, 1]. PAV pools the violating pair (0.2→1, 0.3→0) into 0.5, giving
    p_pav = [0, 0.5, 0.5, 1].
    - B(p) = (0.01 + 0.64 + 0.09 + 0.36)/4 = 0.275.
    - B(p_pav) = (0 + 0.25 + 0.25 + 0)/4 = 0.125, so MCB = 0.150.
    - UNC = B(0.5) = 0.25, so DSC = 0.125.
    - Assert all values exactly (1e-12).
  - Perfectly calibrated synthetic forecasts give MCB ≈ 0.
  - A constant forecast at ȳ gives DSC = 0 and MCB = 0.
  - PAV output is non-decreasing.

## E. Extra leakage negative controls (tests only)
These go in `tests/test_leakage.py` and reuse its `truncation_check`.
- **E1. Same-calendar-day onset count.**
  - The feature: onsets of the unit within the Kyiv civil day containing t, using
    `tz_convert("Europe/Kyiv")` day boundaries, including onsets after t.
  - Leaky witnesses must be caught, pinned from real data and asserted as an exact, non-empty set:
    - (a) an ordinary hour with a later same-day onset;
    - (b) an hour on the 23-hour DST day 2026-03-29;
    - (c) an hour on the 25-hour DST day 2025-10-26.
  - **Causal companion:** the same count restricted to onsets ≤ t must pass `truncation_check` at the same
    witnesses plus the Kyiv midnight hours of those days.
- **E2. Label-derived "hours since last alert"** (the MaksimPrykhodko bug).
  - The leaky feature uses the grid label y(s) = 1 if an onset falls in (s, s+H]. Its value at t is t − max{s
    ≤ t : y(s) = 1}, so the current row's own label is used. Its causal companion is the same with s ≤ t − H,
    i.e. only labels that have matured by t.
  - Witnesses are exact, non-empty, pinned (unit, t) pairs where an onset falls in (t, t+H], including one with
    the onset exactly at t+H (the right endpoint). The leaky version must mismatch there.
  - The causal version must pass at the same pairs, plus two separate boundary checks at each val/test cut-off C:
    - t = C − H, where that row's label window (C − H, C] matures exactly at C;
    - t = C.
- **E3. Onset-collapse check across the Dec-2025 admin reform** (real data, `tests/test_data_quality.py`).
  - Per unit, onsets per 30 days in [2025-09-01, 2025-12-01) vs [2026-01-01, 2026-04-01), from the frozen
    `grid.unit_intervals(alerts, cfg.standing_cap)` onsets, so the D-020 cap applies.
  - Every one of the 24 units must have ≥ 10 onsets in the earlier window, otherwise raise: an
    already-collapsed or near-empty unit is reported, not hidden by an undefined ratio. Fail if any unit's later
    rate is below 25% of its earlier rate.
  - Print the ratios. The 25% threshold is PROVISIONAL.
  - **Synthetic fixture:** two units with oblast-level rows before Dec 2025 and raion/hromada rows after, plus
    one > 24 h standing alert. The check passes on all levels, and fails under an oblast-only mutation
    (`alerts[alerts.level == "oblast"]`).
  - If the real data already fails it, stop and report; do not loosen the threshold to pass.
- **E4.** `tests/test_leakage.py::truncate` gets the A5 docstring note. No witness test asserts the 1h leak (see
  the round-1 disagreement): the leak is kept by human decision and documented in A5, the README and §F.
